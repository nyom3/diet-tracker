# Issue #99: 食事ログ読取方式

## 判断

`food_log` は行順と `timestamp` の順序が一致する保証がなく、過去行の日時編集や古い日時の末尾追記も許容する。末尾から固定行数を読む方式では期間データの網羅性を保証できない。日時列だけを全件走査して対象行を特定する方式も比較したが、対象行が分散すると複数範囲の読取と結合が必要になり、現在のデータ量では呼出回数と実装の複雑さに見合わない。

`readFoodLogsFromSheet` はヘッダーを除く全行を食事ログの10列だけ、1回の `getRange(...).getValues()` で読み取る。期間、未来時刻、直近件数の条件は従来どおり各呼び出し元の日時条件で適用し、`filterEmptyId: false` の意味も維持する。これにより、読み取りセル数は対象行数×10へ増える一方、呼出回数は最大3回+全件フォールバックから常に1回となり、正しさを優先できる。

## 検証範囲

- 603行の先頭当日データ、古い日時の末尾追記、過去行の日時編集
- `recentMealLimit: 3` と未指定
- 7/30/90日、期間境界、未来時刻、疎な期間、空シート
- `filterEmptyId` の既存挙動
- `getHomeSnapshot`、コーチ、週次が同じ読取関数を利用すること、および推移の `getDashboardData` が従来から全件を直接読むことの確認
