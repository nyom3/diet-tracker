# diet-tracker タスク依頼テンプレート

必要な項目だけ埋めて依頼する。既存Issueに要件がある場合はリンクと不足分だけを記載し、要件の正本を増やさない。空欄は権限の委任として扱わない。

```text
対象: diet-tracker
目的: 利用者にとって何ができる状態にしたいか
要件の正本: Issue URL、またはこの依頼

対象範囲:
- 変更する機能・動作
非スコープ:
- 今回扱わない事項

受け入れ条件:
- 具体的な入力・操作 → 期待する結果
- 維持すべき既存動作

委任範囲:
- 調査・提案のみ / 実装・修正・必要な検証まで（選択）
- commit・push・PR・merge・本番反映: 許可する工程を明記

検証・完了:
- 受け入れ条件をどのテスト・操作・差分で確認するか
- 実機や外部環境で必須の確認があれば明記
- 委任範囲内で検証と修正を続け、各条件の証拠を揃えて完了を報告する
- 必須確認が実行できなければ、未完了の項目・理由・再開に必要な条件を報告する
```

## 依頼例

> diet-trackerの食事入力で、送信失敗後に再入力せず再試行できるよう修正してください。失敗時に入力内容を保持し、再試行成功時には従来どおり完了表示になること、送信中の二重送信を防ぐことが受け入れ条件です。実装・修正・必要な検証まで委任します。commit以降は対象外です。関連テストと利用可能なブラウザで確認し、GAS実環境で確認できなかった部分を報告してください。

資料やスキルはAGENTS.mdの参照条件に沿って選ぶ。手順を固定するために全資料・全スキルの読み込みを要求しない。安全制約と実行環境の権限制約は引き続き適用される。

参考: [OpenAI: Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) — 発動条件を具体化し、必要時にガイダンスを読み、着手時に完了条件を定める考え方を採用。
